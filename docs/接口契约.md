# 不忍了当前云函数契约

所有业务函数返回 `{ success, data?, error? }`。错误不能被当作成功或空数据吞掉。云环境在 miniprogram/config.js 配置。

## auth

无业务入参。微信OPENID解析到内部userId，返回 `{userId, isNew, nickname}`。客户端不能自选业务用户身份。

## merchant

- `action=list`：可传 keyword（最多50字符）、category、sort（recommend/rating/sales）、page（1起）、pageSize（1～20）。返回 `{items, categories, page, total, hasMore}`。
- items内含商家基础字段、评分/月售/标签以及 products。商家名命中时展示3个主推商品；仅商品名命中时展示命中的菜品。所有评分和月售均为固定模拟值。
- 查询在本期固定50店的数据集上统一搜索/筛选/排序后分页，排序相同时以稳定ID打破平局。扩容前需要重新评估搜索实现，不能把当前方案承诺为无限扩展。
- `action=detail`：merchantId；返回商家、菜单、当前基准、米饭等值和说明。首页商品结果通过 itemId 路由定位菜单。

## challenge

- 身份来自服务端。客户端的金额、热量、用户ID均不能决定结算。
- `create`：merchantId、items（menuItemId/quantity）、note（最多200字符）、paymentMethod、idempotencyKey（8～100位英文数字下划线/连字符）。只接受同店在售商品；最多50个不同条目、单条1～99份。
- 创建成功 data 是订单，含 `_id/status/items/totalCents/startedAt/expiresAt/serverNow/remainingSeconds` 等。此时没有入账。活动单冲突返回 `ACTIVE_EXISTS` 并带活动订单，当前请求不创建新单。
- `lookup`：同一 idempotencyKey，返回已创建订单或null；提交响应丢失时先查询，确认不存在后以原key、原payload重试。
- `active`：读取并补结算当前挑战。可能返回waiting订单、尚待查看的completed订单或null；不能假设所有非空结果都是进行中。
- `get`：orderId，校验归属，必要时补结算到期单。
- `complete`：orderId，主动提前成功；如果已经到时则按到时成功。
- `giveUp`：orderId，到时前放弃；到时后优先自动成功。已终态返回原结果。
- `ack`：orderId，用户查看成功结果后确认通知已读，仅清除该订单的pendingResultOrderId，不改订单/奖励。

订单状态仅waiting/completed/given_up；完成时返回result快照，包括本次amountCents/caloriesKcal、结算后totalCompleted/walletCents/level/cardId/cardStep/cardCompleted。页面从服务端读取，不从URL参数累计钱包。重试返回同一订单的结算结果。

客户端以serverNow/remainingSeconds校时，计时显示优先使用单调时钟；本地到零只查询get，不能自动调用代表主动成功的complete。离线complete/giveUp按用户隔离保存，联网时重试，不采用离线本机时间追溯提前成功。

## 管理函数

initDatabase、seed仅用于必要的环境建设，从管理端执行，拒绝带微信客户端OPENID的调用；已有环境不重复运行，发布前停用云端管理入口。

## personal

与challenge一样从微信身份解析内部userId，返回`{success,data?,error?}`；不能通过参数选择用户。时间为服务端时间，北京日期用于打卡、木鱼和统计。

- `summary`：无业务入参；返回user、state、preferences、currentWeight、goal、30天trend、checkin、successStreak、6项badges、nextLevel、week和已设置的background。周统计读取成功订单的实际完成时间，按本周截至当前与上周同期对比。
- `profile.save`：nickname（1～20个字）、可选avatarAssetId；头像必须是本人ready且purpose=avatar的媒体，空参数保留原头像。
- `preferences.save`：soundEnabled布尔值。
- `checkin`：无日期入参；北京时间当天一次，返回date/already。同一事务累计checkinDays并解锁符合条件的七日记录徽章，不推进拼图。
- `calendar`：month为YYYY-MM；返回days，逐日包含checked/completed/amountCents/caloriesKcal/grams，另含today。手动打卡、挑战成功和体重分别显示。
- `wallet.list`、`weight.list`、`diary.list`、`cards.list`：page从1开始，每页20条；返回items/page/hasMore/total。diary.list另含现存正文总words，摘要只返回正文前80字符。
- `weight.add`：grams（整数，10000～500000）、requestId；相同请求ID返回同一记录。每日可多条，以时间和sequence确定最后记录。
- `goal.save`：targetGrams、requestId；必须已有当前体重；关闭上阶段并以最新体重开启新阶段，重复请求不再建阶段。
- `woodfish.get`：当前服务端北京时间date、count及serverNow。
- `woodfish.add`：date、deviceId、total（设备在该日的累计值）。只增加相对已确认值的正差，旧日待同步仍归旧日，拒绝未来日期。返回count/date/acknowledged/serverNow。
- `diary.get`：id，返回本人现存正文、情绪、version及时间。
- `diary.save`：id、body、mood（空/平静/开心/焦虑/委屈/疲惫）、version、可选challengeOrderId。最多2000字；相同正文/情绪重试返回原记录；版本冲突返回EDIT_CONFLICT。关联订单必须属于本人。
- `diary.delete`：id；去除正文，保留删除标记阻止迟到保存请求复活。现存日记统计不含删除记录。
- `presets`：启用且含真实fileID、有效width/height的系统图库，按sortOrder排序；未配置时返回空数组，不伪造图片。
- `card.get`：可选id；不传时读取当前活动卡，未开始则null。返回fileID、imageWidth/imageHeight、gridColumns/gridRows、tileCount、layoutRevision和真实翻块位置；开发期未配置图片的卡在首次资源可用时固定图片快照。
- `card.background`：id及presetId或assetId（二选一）；仅本人进行中卡可换，保留成功步骤；同网格保留翻块位置，网格改变按floor(N×k/7)稳定重排并增加layoutRevision；个人图片必须本人ready且purpose=card。完成卡返回CARD_LOCKED。
- `background.set`：id，只接受本人的已完成卡。
- `media.prepare`：requestId、purpose（avatar/card）、format（jpg/png）；返回_id/cloudPath/status。私人开关未启用时MEDIA_NOT_READY；云路径由服务端生成。
- `media.commit`：id、fileID；核对本人资源、随机路径和实际云文件JPG/PNG格式、元数据、体积（不超过10MiB）及EXIF方向，返回width/height/format/orientation/sizeBytes，尺寸只信任服务端读取结果。上传成品长边不得超过2048px。2026-09-11前端取消原图大小/格式门槛，先自动优化可解码图片至长边2048px以内及目标2MiB以内，必要时转JPG、降质量/尺寸；处理不改变接口，云端不直接接收任意原图。头像优化后裁剪1080方图。

公共图通过云存储公开读取，个人图片通过创建者权限读取。个人数据不允许客户端直接读写数据库。查询集合超过100条时按_id游标继续读，不静默截断；所需10个新查询索引见《数据库索引》。

新增接口本地测试和微信模板/样式编译已通过，真实SDK/权限/上传/设备效果仍须在协同部署完成后验收。
