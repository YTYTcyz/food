# 不忍了云数据库设计

原生微信云数据库文档模型；不是关系型SQL/Prisma方案。业务集合按当前规则设计，不实现旧规则兼容层；已生成的新版测试数据在部署前单独核对，不能视作空数据库。

## 已有基础集合
- users：内部用户ID、默认昵称头像、时区Asia/Shanghai。
- auth_identities：userId、provider、providerSubjectHash，微信身份关联。
- merchants：name、category/categoryName、rating、monthlySales、tags、featuredItems、searchItems、searchText、模拟来源、封面、sortOrder、isActive。
- menu_items：merchantId、name、imageFileID、priceCents/priceSource、estimatedCaloriesKcal、portionLabel、sortOrder、isAvailable。
- nutrition_references：code、kcalPerUnit、version、isActive；当前 nr_cooked_rice_bowl_v1，通过配置该文档数值和版本调整基准。

## 本轮挑战结算使用
- challenge_orders：内部用户、稳定幂等ID、单店商品快照、金额/配送费、备注、装饰支付方式、固定地址、waiting/completed/given_up、startedAt/expiresAt、completedAt/completionReason/successDate、givenUpAt、result。
- user_state：以userId为_id；activeOrderId锁、pendingResultOrderId、总成功次数、钱包分、模拟热量、完成卡数、手动打卡日数、卡序号/活动卡ID、level。读写此文档保证同用户创建/结算互斥；不是独立积分系统。
- wallet_ledger：以orderId为_id，成功金额、商家、effectiveAt和successDate；只有成功流水，无预入账或回滚分录。
- daily_successes：以userId_日期为_id，成功次数、金额、热量；用于日历/连续挑战天数/重算。
- memorial_cards：用户、背景来源/系统presetId或私人assetId、imageWidth/imageHeight（显示方向宽高）、gridColumns/gridRows、tileCount、layoutRevision（换网格递增，用于解释历史记录，不用于旧业务规则分支）、currentStep、totalSteps=7、revealedTileIndexes、active/completed、创建完成时间。
- memorial_card_progress：以orderId为_id，用户、cardId、challengeOrderId、stepIndex、effectiveAt、successDate、此次翻块位置、当时layoutRevision/gridColumns/gridRows/tileCount快照。换图后历史记录不改写为新位置，新网格以卡片当前记录为准。
- user_achievements：以userId_code为_id，徽章代码、名称、首次解锁时间。

订单完成、以上奖励写入使用单一事务，无where事务查询；事务外身份解析后仅按内部userId执行。参考 [CloudBase官方事务说明](https://docs.cloudbase.net/database/transaction)。结算查询和记录时间分开，自动成功时间固定为expiresAt。

## personal个人业务集合
- daily_checkins：userId、date、createdAt；北京时间手动签到，同日唯一。
- woodfish_daily：userId、date、count、devices；按device_设备ID保存累计确认值，只增加累计值的正差，乱序和重复请求不重复计数。旧日待同步归旧日，无历史页。
- diary_entries：userId、challengeOrderId可空、mood、body、wordCount、version、createdAt/updatedAt；草稿在本机按用户隔离。相同正文重试返回原记录，不同正文检查version；删除去除正文并保留deleted墓碑防止旧请求复活，列表和统计排除墓碑。
- user_goals：用户、阶段ID、起始/目标体重克、起始时间、active/closed；换目标新阶段。
- weight_records：userId、stageId、grams、recordedAt、sequence；userId_请求ID保证幂等，同日多条保留，同毫秒按sequence确定最新。user_state补充currentWeightGrams/currentWeightAt、weightSequence和activeGoalId，与挑战和打卡共用事务锁。
- user_preferences：资料及音效偏好；无身高/BMI/热量预算。
- media_assets：ownerUserId、purpose（avatar/card）、cloudPath、status（pending/ready）、fileID、format、width/height（含方向）、orientation、sizeBytes、时间；客户端先申请随机私人路径，上传成功后确认，资源引用必须校验本人归属。私人开关未启用则拒绝准备和确认。
- memorial_presets：稳定presetId、名称、真实fileID、width/height（显示方向宽高）、cloudPath、排序、启用；默认card-01，尺寸从实际素材提取，不再统一填写1080。
- user_profile_backgrounds：userId、completed卡ID。

memorial_cards中的backgroundFileID保存固定图片快照，后续图库变化不改变已固定的资源。尚未绑定图片的新卡使用6×6占位，首张图片可用时按实际比例与已有成功次数重新分配亮块。

动态网格不需要新增集合或索引。部署与测试数据状态见《实施状态》；不增加运行时旧规则兼容或自动清库逻辑。
