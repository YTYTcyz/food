# 不忍了数据库索引清单

集合创建由 initDatabase 执行，索引在云控制台手动建立。需求调整前没有旧订单，不做旧版兼容。

以下索引已按用户完成结果配置；当前部署状态统一见《实施状态》，不重复创建。

## 唯一索引
- auth_identities：provider升序 + providerSubjectHash升序。
- nutrition_references：code升序 + version升序。
- challenge_orders：userId升序 + idempotencyKey升序。
- wallet_ledger：orderId升序。
- daily_successes / daily_checkins / woodfish_daily：userId升序 + date升序，各集合分别建立。
- memorial_card_progress：challengeOrderId升序；cardId升序 + stepIndex升序。
- user_achievements：userId升序 + code升序。
- user_state / user_profile_backgrounds / memorial_presets：使用确定的_id，无需同义额外索引。

拼图按成功次数推进，memorial_card_progress不能使用cardId+progressDate按天唯一约束；user_goals保存多个阶段，不能使用userId单列唯一约束。

## 查询索引
- merchants：isActive升序 + sortOrder升序。固定50店由服务端统一搜索排序分页，尚无扩容搜索承诺。
- menu_items：merchantId升序 + isAvailable升序 + sortOrder升序。
- challenge_orders：userId升序 + completedAt降序（历史查询）。
- wallet_ledger：userId升序 + effectiveAt降序。
- diary_entries / weight_records：userId升序 + createdAt或recordedAt降序。
- memorial_cards：userId升序 + status升序。

索引不能单独防止不同幂等键并发下单，user_state事务锁仍必需。

## 分页查询索引

以下均为非唯一、全部升序；已有原索引保留，不重建集合。

- weight_records、user_goals、daily_checkins、daily_successes、user_achievements、wallet_ledger、diary_entries、memorial_cards：每个集合分别建立userId + _id。
- challenge_orders：userId + status + _id。
- memorial_presets：isActive + _id。

共10个查询索引，服务端按_id游标逐批读取，支持超过100条记录；面向用户列表再按记录时间排序并分页。前8个集合索引名为query_user_id，后两项分别为query_user_status_id和query_active_id。更大数据量下需评估聚合/查询耗时，不把当前本地测试当作真实P95达标证明。
