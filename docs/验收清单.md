# 不忍了验收标准

本文是开发者及最终质量检查依据，完整功能尚未验收。当前配置与已有验证见《实施状态》；剩余协同完成后，按实际部署版本另行给出逐页用户验收清单。未依赖私人图片的功能可以先行验收。

## 部署完成后的检查依据：真实提前成功结算

1. 先重新打开小程序，处理已有订单的待展示结果或到期补结算，再记录当前用户的user_state和当天daily_successes作为基线。按现存数据计算增量；验收过程中不清库或手改统计来凑预期值。
2. 正常新建一单，记录challenge_orders中的_id、userId、totalCents、estimatedCaloriesKcal、startedAt和expiresAt。此时应为waiting，只保存快照；本单尚无钱包流水/拼图进度，用户累计成果不增加。后续检查均按同一个订单ID和内部userId定位。
3. 在服务端到期前点击“我已不想吃了，取消订单”。确认返回成功结果；订单应为status=completed、completionReason=early，completedAt为服务端收到操作的时间且早于expiresAt，successDate为该时间对应的北京时间日期。
4. 在云数据库控制台只读核对：wallet_ledger中该orderId恰好1条，amountCents等于订单totalCents；user_state.totalCompleted较基线加1、walletCents增加本单金额、totalCaloriesKcal增加本单热量；对应日期daily_successes的completed加1、amountCents和caloriesKcal同步增加。等级按累计次数门槛核对。
5. memorial_card_progress中该challengeOrderId恰好1条，指向实际推进的memorial_cards记录，currentStep推进1步。新卡从第1步开始，累计亮块为floor(N×k/7)，N为该卡当前总块数，k为成功次数；正方形依次新增5/5/5/5/5/5/6块，54块依次新增7/8/8/7/8/8/8块，第7步全部点亮收藏，下次成功才开新卡。符合门槛的user_achievements只解锁一次；已有徽章不重复新增。挑战成功不写daily_checkins。系统图库已有实际配置，需同时核对图片显示；数据写入与视觉结果分别记录。
6. 在小程序调试上下文中对同一个orderId重复调用challenge（action=complete），再查询结果；以上流水、统计和拼图均不得再次增加。此操作使用真实小程序身份；不能用管理端无OPENID调用替代用户链路。记录订单ID、调用结果、前后增量和异常信息，不记录身份凭据或私人内容。

提前成功通过后，分别用新订单验证到时成功和到期前“还是吃了”：到时或重开补结算应completedAt=expiresAt、completionReason=timeout；到期前放弃应given_up且无本单奖励。再验证断网队列、并发、跨午夜日期和事务失败整体回滚；单次成功不等于这些异常场景也已通过。

## 本轮本地可验证
- 搜索分类排序分页组合，50店500菜品不重不漏，价格与图片不丢失。
- 各店独立购物车、已有项增减、无起送限制、商品费+150分。
- 重复提交同key一单；不同key同用户并发只一单；客户端伪造金额或跨店菜品不能生效。
- 提前成功、到时成功、到期前放弃、到期后自动成功；重试幂等。
- 跨午夜实际到时归属、延迟补结算、结算中途失败整体回滚。
- 同日7次集齐一张动态拼图，第8次新卡；方图36、1980×1280横图54、1280×1980竖图54，极端比例最多144块；钱包/次数/等级/徽章一致。

## 云端与真机（配置已完成部分，行为仍待协同验收）
- 真实事务SDK与唯一索引行为、客户端拒绝读写及跨用户鉴权、结算耗时与网络错误；已配置的索引/数据库权限/10秒函数超时不再重复当作未部署。
- 订单提交弹层从创建时计时；改本机时钟不改变服务端到时点。
- 关闭重开、断网操作队列、非强制工具跳转、草稿保护、图片失败。
- 320～480px竖屏，iOS/Android各一台；固定设备网络记录P95，常规首屏2秒/接口3秒目标，冷启动单列。

## 工具与个人中心完整验收
- 木鱼当日累计、日记草稿编辑删除及鼓励库、原图/RB混合图、工具共享挑战时间。
- 手动日历与挑战标记分离、钱包明细、6徽章、阶段体重与7/30日趋势、上周同期。
- 6默认图片实际读取，上传换图保进度，完成收藏锁图与主页背景。
- App入口无地址时说明未开放，无可提现承诺；跨用户私有数据隔离。

只有全部当前确定功能通过才算MVP验收完成；本轮代码测试通过不等于云端/真机/整体验收完成。

## 动态拼图增量质量检查（部署及素材前提满足后）

- 方图、横图、竖向人像：完整照片不拉伸、不切头脚；预览、拼图、已完成主页背景比例一致。带EXIF方向的手机照片在iOS和Android分别核对。
- 1980×1280显示9列×6行、54块，7次按7/8/8/7/8/8/8新增；系统card-01为6列×9行，其他当前系统图为66块，7次必定集齐。
- 第3次后换不同网格，currentStep仍为3，亮块数按新总块数重新计算，刷新不重抽；继续4次后集齐。相同行列换图保留位置，完成卡拒绝换图。
- 成功与换图并发、响应丢失后重试：订单和钱包不重复，卡片步骤不丢失，历史进度可用当时布局解释。
- 超长横图/竖图最多144块，画面完整；小图不放大，超过10MB原图不直接拒绝，自动优化并核对成品实际体积，目标不超过2MiB、长边最多2048px。较大PNG/可解码其他格式必要时转JPG，透明区域铺白底、动图静态化；损坏/无法解码/处理失败可重试，原件和原卡图不变。
- 云数据库media_assets中的宽高与上传成品实际显示方向一致；伪造客户端width/height不能更改网格奖励。
