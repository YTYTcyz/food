# 不忍了数据权限与隔离

## 数据库与业务身份

merchants、menu_items、nutrition_references、memorial_presets四集合公共只读；其余17个业务集合禁止客户端直读直写。云函数从微信OPENID关联内部userId并核对记录归属，不信任客户端传入的用户ID。日记正文、体重和私人图片内容不进入日志或埋点。

## 云文件

`deploy/storage-rules.json` 是当前已保存的完整规则：shop_pic/与memorial-presets/公共只读，private/要求登录且文件创建者OPENID与当前身份一致才能读写。该环境使用直接 `.test()` 结果，目录匹配分开书写，不加入 `== true` 或正则分组。保持边界回归测试。

media.prepare生成随机私人路径；media.commit检查本人归属和路径，再读取实际云文件校验格式、大小、EXIF方向与尺寸，成功后才允许绑定。草稿、待同步敲击和体重请求在本机按内部userId隔离。日记删除清除正文，保留删除标记防止迟到请求复活。

## 开启与验证

私人媒体使用前端配置与personal环境变量的双开关。规则保存、A自身读写成功不能替代B跨用户测试；完成 [用户协同操作清单](用户协同操作清单.md) C04后才开启C05。当前进度只在 [实施状态](实施状态.md) 更新。

权限验证须使用两个真实小程序身份对仍存在的同一文件直接请求。临时签名URL、管理端调用、文件不存在或普通网络失败不能证明用户隔离。业务接口跨用户鉴权与云存储隔离分别验收。

initDatabase和seed是管理工具，拒绝客户端调用，发布前停用或删除云端实例；遗留的storageProbe云端探针也需清理。相关源码本轮保留；本地文件整理不改变云端实例。
