## 用户图片

2026-09-11按用户要求取消原文件10MB门槛和JPG/PNG输入白名单。用户直接选择相册/相机图片，无需先改大小；微信/设备能解码的图片均尝试处理。特殊格式取决于实际设备，损坏或无法解码的文件提示重试/换图。

`miniprogram/utils/image-upload.js`在上传前自动优化：较小JPG/PNG在长边不超过2048px且体积不超过2MiB时保留，PNG保透明度；大图先原生等比缩小，读取产物的实际体积和方向尺寸。仍偏大或需要转格式时，用2D Canvas绘制整图、铺白底后导出JPG，质量依次0.82/0.65/0.45；仍超目标则降长边至1536/1024/768/512继续尝试。小图不放大，原图不裁切，达到目标才交给上传，不能只改扩展名。

预览使用最终处理后的图片；转JPG会移除透明度，动图保存静态画面，页面提示确认预览，相册原件不被覆盖。尝试次数有界，结束后释放Canvas缓冲，只清理本次生成且未采用的中间临时文件，保留成品和原件；卸载后停止后续处理。

头像复用自动预处理，随后可拖动/缩放裁剪为1080方形JPG。服务端继续校验成品为JPG/PNG、长边不超过2048px、体积不超过10MiB，这是云端成品校验，不限制原图选择。前端目标2MiB低于已部署上限，无需改云函数或重部署。

上传流程：选择并自动优化 → 预览确认 → personal/media.prepare申请带成品格式的随机私人路径 → 上传显示进度 → media.commit从实际云文件读取格式、大小、方向及宽高 → ready资源绑定卡片。云端不信任客户端上报尺寸。处理失败不上传、不应用卡片；确认阶段失败在原页重试同一已上传文件，新选图片申请新资源路径。

## 权限与状态

使用deploy/storage-rules.json：公共shop_pic和memorial-presets只读，private限上传者本人读写。完成双用户检查后，同时开启personal环境变量PRIVATE_MEDIA_READY=true和miniprogram/config.js同名开关；默认关闭时不上传真实私人图片。

当前上传、规则及跨用户测试进度统一见《实施状态》，剩余权限操作见《用户协同操作清单》C04/C05。图片方向、压缩与真机显示属于功能验收，不能由权限配置结果替代。
